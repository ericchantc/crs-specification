# Contributing to CRS

CRS is a published draft specification. Contributions take the form of expert feedback and threshold review.

## How to contribute

### Open an issue

Use the issue templates to:
- **Threshold review**: challenge or support the CR >= 0.80 / ECE < 0.05 thresholds with empirical evidence
- **Review feedback**: share what you found when reviewing or evaluating CRS (gaps, ambiguities, edge cases). No permission to implement or pilot CRS is given; write to contact@vacra.ai first
- **Schema feedback**: missing fields, unclear definitions, or JSON Schema issues in `crs-v0.1-schema.json`

### Before you submit

- Check existing issues first
- Reference the relevant field name or pillar (e.g. F5 `calibration_rate`, Pillar 2)
- If citing a paper, include the DOI or arXiv ID

### What thresholds are open for challenge

All threshold values (CR >= 0.80, ECE < 0.05 / 0.10) are the author's proposal and are explicitly open for challenge. If you have evidence from a specific deployment domain (medical AI, credit scoring, fraud detection), open a threshold-review issue , that is exactly the kind of feedback that improves the standard.
